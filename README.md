## 阅读怎样连接起来

```text
原书 → 有页/行定位的内容单元 → AI 选择读书法并顺序精读
                               ↓ 实际调用插件工具
             类型、人物/概念、事件、地点、参与者与有来源的关系
                               ↓ 共用对象 ID
             卡片 ↔ 地图与时间轴 ↔ 关系图谱 ↔ 原文依据

用户理解 / 主动保存的 AI 回答 → 真实 Markdown → 文档导图节点
```

例如读到一场战役，AI 可以创建战役事件、地点和参与人物，再把同一个事件关联到地图与时间轴；点击任何入口都围绕同一个对象展开。数学书可以使用定义、定理和证明依赖，不需要人物或地图。

- 预读选法、动态类型与方法、真实工具调用、顺序阅读、覆盖记录、暂停/续读、请求预算、逐层复盘与全书综合。

- 读书法进入逐步执行流程。知识抽取步骤必须实际变更合适的知识对象，或说明无变化理由；引文核验在本地执行，检查来源与关联，不冒称语义正确。完成步骤与失败检查点按次保存，重置重试预算后仍需用户继续精读才发请求。
- 模型切换/新建前确认保存、放弃或取消，保留未保存输入与密钥；非法 OCR 范围单独报错，显示本轮将识别、跳过及剩余页数和原因。设置/插件页就地反馈，添加组件后留页，显式“打开”才导航。
- 卡片在当前详情内编辑，必填/已填字段优先、空的可选字段折叠；切对象或关闭前保护草稿，失败保留输入。聊天从保存菜单进入多选，选择结束可取消，不常驻每条回答的复选框；局部错误不再叠加同一全局提醒。
- 图谱节点和端口使用原生窗口事件与位移，绝对位置预览保留到保存回调；单次拖动开始时才发布选择，静态平铺网格与固定占高的保存反馈减少重排。仍需验证滚动、拖出卡片、失败回弹、端口连线和底栏稳定。
- 时间端点拖动的边界与宽度快照、切书/离页/取消，以及同年、负年份和缩放中的行为列入集中验收，尚无 Mac 手势通过结论。
- 合并展示的组件入口一并移除旧重复别名，避免删除后再次出现；不同筛选的卡片入口保持独立。移除只影响入口，重新添加仍可查看原知识对象。

这里的扩展能力是**随源码编译的原生注册接口与受控声明包**；没有任意代码热加载或任意生成原生视图，也不声称已经等同 DeepSeek Harness。

沿用的 0.6 操作方式：

- 时空页默认使用小地图标记，选中后才展开名称；事件清单从“事件”按钮打开。时间范围离开页面再返回仍保留，点击同一事件也可重新定位地图。
- 图谱不放常驻“打开/写理解/连线”按钮或连线表单；节点边缘圆点、右键与双击就地操作。图谱的来源/关系详情通过右键或双击相应对象用本地弹层查看，保持画布宽度；卡片也可直接点击查看完整内容。
- 我的理解使用单行编辑操作区，笔记选择器提供标题搜索与新建；标题直接修改后保存，不再另设重命名菜单。知识库按笔记/分析/要素分区，搜索跨全部分区，阅读分析按需展开。
- 回答摘记使用同一个保存弹窗：标题固定在上方，只读 Markdown 连续选择与即时预览同页，底部一次“保存摘记”；没有另行预览再返回重选的步骤。语义文本、公式/图片源文差异、问题与引用说明保留，失败不清空标题或选区。
- PDF 搜索只用独立放大镜按钮或 ⌘F；区域框选只放在高亮菜单。AI 服务保留侧栏展开栏与窗口工具栏入口，去掉重复设置齿轮和更多菜单中的 AI 配置项；窗口更多菜单与侧栏导入导出菜单保留。
- 插件、类型、读书法和高级模型参数折叠显示；设置/OCR 的确认操作固定在底部。工作流收起方案、记录和综合，待核对/失败仍有可见摘要与入口，执行按钮不在多处重复。

工具变更先在当前步骤中校验，每一步保存检查点；只有逐段回执、所选步骤及完成门禁齐全后才提交单元覆盖。失败或取消保留最后一次已保存结果；地图和时间轴不各存一份事件。

0.3 的顺序是“宿主清单 → 段落回执与检查点 → 回执齐全 → 带完整原文的知识提取 → 读书法步骤结果 → 综合”。AI 不能自己减少清单、缺一段就宣布完成，回执和原文哈希不匹配也不能过关。旧版已有笔记保留，但不会被补造为具有逐段回执；延期未识别页仍是未读，可补 OCR，不能进入完整综合。

## 在 GitHub Actions 构建

仓库提供手动工作流 **Build macOS App**，不在每次小修改后自动打包。

1. 在 GitHub 的 Actions 中选择工作流，点击 **Run workflow**。
2. 工作流在 `macos-26` / Xcode 26.6 运行核心检查、编译 arm64 和 x86_64，合并为 Universal App。
3. 成功后下载 `ReadingBook-macos-universal` artifact，解开外层 artifact，再解开其中应用 ZIP。
4. 把 `ReadingBook.app` 复制到 Mac 的应用程序目录，手动启动验收。

产物同时附 SHA-256 和源码 commit。应用包使用临时签名，没有 Developer ID / Apple 公证；首次运行可能需要在系统“隐私与安全性”中对该应用单独允许打开。不建议关闭 Gatekeeper。

Mac 本地构建（需要 Xcode 26 SDK，运行系统 macOS 15+）：

```bash
swift test --scratch-path .build/tests
bash scripts/build-macos.sh
```

## 第一次使用

1. 导入 `Examples/math-sample.md` 或自己的书。密码 PDF 按提示解锁，取消可退出导入。
2. 在窗口工具栏的 AI 服务入口管理/新建配置，选择模型预设并填写 API Key，保存或发送一条短文本测试。本机兼容服务可不填密钥；文本测试不能证明工具/视觉能力。
3. 扫描 PDF 从浮动阅读工具的阅读选项菜单进入 **OCR**，选择图像模型和页码识别；对照原页核对。通过侧栏或 ⌘2 打开阅读流程预读，检查方法、组件后启动精读。预算包含工具续轮。
4. 在原始 PDF 选择文字，从高亮菜单添加高亮，或选择扫描区域框选后填写评论；在批注列表编辑、删除和恢复。搜索用放大镜/⌘F，区域批注不自动 OCR，也不增加阅读覆盖率。
5. 侧栏或 ⌘1–4 切换原文、流程、对话和我的理解；卡片与图谱的详情按需弹出。时空页拖动双端点筛选范围，或点击年份输入精确区间，再从同轴事件点/事件清单定位地图。
6. 从“笔记”选择器搜索/新建自己的理解，直接编辑标题后保存；在对话保存弹窗内选段、查看即时预览并保存。在思维导图从边缘圆点或右键直接连接节点，双击节点打开文档；双击连线名称即可改名。
7. 导出书项目，在副本中导入，核对原书、批注、文档与关联。

文本默认支持 UTF-8 与带 BOM 的 UTF-16/32。兼容 Chat Completions 接口可选择 `max_tokens` 或 `max_completion_tokens`，保留工具续轮需要的 `reasoning_content`。远程服务要求 HTTPS，本机 loopback 可用 HTTP。开发过程中不会自动调用模型。模型目录的版本和官方资料见 [provider-catalog.json](Sources/ReadingBook/Resources/provider-catalog.json)，核查日期 2026-10-14；账户、区域、别名规格可能变化。Max 是输出上限，实际请求仍受上下文余量约束；未核实精确整数的规格保留未知，不猜 Max。Claude 的兼容接口与原生 Messages 功能不完全相同。

公式验收可导入 [排版示例](Examples/math-rendering-sample.md)。渲染资源全部随 `.app` 打包，不依赖在线 CDN；依赖版本、MIT 许可与文件哈希见 [第三方说明](Sources/ReadingBook/Resources/Markdown/THIRD_PARTY.md)。Markdown 不执行原始 HTML；远程图片不自动加载，本地相对图片只读取明确授权目录中的安全栅格文件。

## 数据与当前限制

数据位于 `~/Library/Application Support/ReadingBook/books/<book-id>/`：`project.json` 保存结构、提取文本与 PDF 批注，`source/` 保留原书，`docs/*.md` 是文档正文，`.journal/` 用于中断恢复。保存后的 API 密钥进入 Keychain，服务参数与文档草稿进入本机 UserDefaults；未保存的模型配置输入和密钥仅保留在本次进程内存，退出 App 不作为已保存配置恢复。PDF 打开密码也仅存进程内存，不写入这些位置或导出包。

密码 PDF 的原始文件仍保留原加密字节，**书库不是整库加密**：已提取/OCR 的文字、聊天、批注和 Markdown 笔记仍按普通本地格式保存、导出，不继承 PDF 密码保护。

- 处理覆盖不等于理解正确。引用校验只能确认原文存在，不能自动证明推断正确。
- 清单严格覆盖已导入的文本；原有单元可能在长段中分片，界面明确标出片段。它不能证明 PDF 提取/OCR 没漏掉图像中的文字，也不能证明 AI 内部注意力或语义理解绝无遗漏。扫描页、图表与复杂公式仍需对照原页；回执复述使遗漏更容易核查。
- OCR 使用支持图像输入的模型，服务不支持时明确失败。已有分析或笔记引用的页面不能覆盖；需要重新识别时将原书导入为新项目。图表、手写、小字、复杂排版仍需对照原页核对；不清楚内容保留标记，识别不等于阅读覆盖。
- Markdown 正文原样保存；公式使用 KaTeX 支持的 LaTeX 数学语法，不是完整 TeX 文档编译器。不支持的命令显示原式和错误；EPUB 样式/嵌入资源与任意 HTML 页面尚不完整支持。
- 渲染区摘录保存可见语义文本，不声称还原原始 Markdown / TeX；公式应使用“选择 Markdown 片段”，并选全分隔符。源文片段必须与对应原答的连续文字完全一致，不能编辑后冒充原答。
- PDF 文字高亮依赖 PDF 的可选择文字；扫描图片用区域批注。区域一次限同一页，跨页拖框拒绝保存；文字跨页选择则按页分别记录。批注不写回原 PDF，原书权限禁止复制时不绕过限制。
- 书籍移至本机 `ReadingBook/trash/`，文档以回收标记保留原 `.md` 与节点，可在回收站恢复；回收文档不会进入 AI 文档检索。删除实体/事件清理结构化关系，原文和用户正文保留，此类对象没有一键恢复。移除画布节点保留文档，可重新加入导图。
- 地图为系统 MapKit，底图需要网络。未知地点不凭空地理编码；可在地点卡中手动补坐标与依据。
- 声明包扩展现有类型、方法与视图组合；原生工具和组件通过注册接口扩展，增加原生实现仍需源码编译。原生接口不是任意代码沙箱；没有热加载、插件市场，也未承诺与 DSH 插件格式兼容。
- 现阶段未做云同步、Lumen/HistoryandKnowledge 数据兼容、商业签名或自动更新。

产品参考：[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的插件组合，[Lumen](https://github.com/theincrediblewwz/lumen) 的文档节点，以及作者本地 HistoryandKnowledge 的时空联动。本项目独立实现，未复制这些项目的源码或真实数据。
