# AI 协作、配置与共享资料一致性

本批目标：真实核查现有 OpenCode Go / DeepSeek；统一对话整理、智能阅读与并行保存的人物身份；优化共享资料合并。原书、笔记、分析、自动保存及轻量防剧透沿用原设计，没有书库迁移或第二套组件资料库。

## 已确认的问题与改动

| 问题 | 处理与边界 |
| --- | --- |
| HTTP 429 只提示核对授权和额度 | 真实响应明确为上游过载。传输层最多读取16 KiB错误前缀，接到HTTP响应后最多等待250ms；只映射固定中文原因和有效重试时间，不显示原始响应、地址或密钥。不自动重复收费请求。接到HTTP之前的网络等待仍由原超时控制。 |
| 重新选择预设后连接成功，怀疑配置读取 | 前后服务ID、模型、地址相同，输出上限384000→8192；连接测试两者都限制512，准备的请求正文相同。实际AppStore新实例读到当前保存的完整配置和对应密钥，未重选预设仍收到明确过载。未把此现象直接归因为密钥丢失。 |
| 配置读取失败时可能先切换名称和模型，后读取密钥 | 先完整读取配置与对应密钥，再一并发布；失败保留原匹配状态。损坏或重复标识的配置明确报错，不静默退回legacy。仅给测试提供可注入的本机密钥存储，正常安装路径不变。 |
| 旧连接测试结果可能落到已修改的配置上 | 核对完整ProviderSettings及服务ID、密钥和书库归属；输出、上下文、参数名、请求上限改变后均须重新测试。 |
| 对话整理入口可重复创建同名对象 | 与旧分析和并行合并共用事务内身份索引，检查繁简、全半角、大小写、原名及别名。检查最终有效状态，连同批次内晚加的别名一起核对。保留音调、标点和完整长名称，不擅自合并；同名不同对象可先消歧。 |
| 仅保存回答也重建全书身份索引、反复编码未变化资料 | 利用Swift值数组仍共享同一存储这一充分条件，跳过未变化人物、事件、关系的重复编码；不同存储仍走原精确JSON合并。未用ID、数量或普通字符串相等推断无变更，保留并行修正与实际UTF-8变更。 |
| 关闭错误弹窗触发界面更新内发布状态 | 实际调用栈落在WorkspaceView的alert绑定、AppKitDialogBridge.dismiss和ViewGraph.updateOutputs。下一轮再关闭，以版本号拒绝旧回调清除新错误，连相同文字的新错误也保留。同一40项流程告警56→0。 |
| 已空的句子浮层仍重复发布清空通知 | 只发布实际变化字段，原任务取消与代次失效仍立即执行。独立断言检查空清理0次、活动状态正常清除。该改动本身未消除前述56条告警，告警的实际修复是弹窗关闭路径。 |

## 更换为 DeepSeek 官方后的真实检查

用户在已安装程序中新建并选中官方 `deepseek-flash` 服务，自己填写并保存密钥。实际新 AppStore 实例无须重选预设即可读回相同的完整配置和对应密钥，短文本测试首次成功，耗时0.631秒。只在进程内读取密钥，不复制、不打印、不将其当作普通偏好写入证据。

第一轮使用三页合成书和正式对话/组件工具，5次真实请求后自动保存并挂载人物、事件、关系、笔记联动工作台。8项直接检查通过：冻结在已读第1页、不混入第3页对象、笔记在本地联动、原文与笔记字节保留。未向模型发送本地笔记。五类原生运行告警均为0。这证明该配置可以实际调用工具，不代表所有自然语言请求都已稳定成功。回答对一条已存在关系的概述仍有遗漏，不能把工作台正确显示等同于回答内容完全准确。

第二轮复制第一轮保存的合成库，添加一条读者修正，移动到第2页，用产品“继续整理”准备问题再发送。最多8请求、每请求输出4096；模型读取两页、保留原工作台及修正，尝试提交带原文的张飞/重逢补充，但在可选eventMetadata中填入未定义的typeID，原有时态校验正确拒绝了整份提案，未将错误资料落盘。达到请求上限的收尾回答又出现DSML式工具标记；该轮明确记为失败，不能用首轮成功掩盖。8次响应报告的输入加输出总token为167285，未取得完整输入/输出/缓存分项，不估算精确账单、不声称一定比Go少耗token。

此后不连续重复收费试验，先以保存的合成请求和回答做离线反例。下一批优先：让模型获得当前确切的事件类型/已有对象边界，给校验失败提供可修正的信息；到达预算时生成明确的完成/未完成说明，内部工具标记不能当成正常答案。保留原子提交、严格原文核对、读者修正、已有工作台复用和预算，不能用放宽校验或不断增加请求次数换取“通过”。随后减少重复能力结构进入上下文的成本，并以同一问题和工具结果做对照。这里是后续工作，不冒充0.23.60已经实现。

真实证据入口：`logs/ai-collaboration-20261106/deepseek-official-summary.json`；三个子目录为`deepseek-official-profile`、`deepseek-official-workbench`、`deepseek-official-continuation`。原书库在宿主中拒绝访问，测试保存全部限于合成书。首轮5次、续轮8次加短文本1次，共14次官方调用；Go的1次短文本成功、4次过载记录另计，不能合并成官方模型的成功率。
