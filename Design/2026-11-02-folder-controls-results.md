# 文件夹列表：按需显示与操作目标保护

本批产品为 0.23.39/build70。修改 `ReaderFolderControls.swift` 的文件夹筛选和“移到文件夹”两条入口：当前类型超过 12 个文件夹时按需创建可见行，少量仍完整创建。不改变文件夹排序、层级、原文权限、数据格式或保存位置。

## 已确认并修复的问题

用真实原生弹窗和隔离合成书复现了三种错误：重命名期间原文件夹被删除，保存会误建文件夹；重命名期间选中另一文件夹，保存会改错目标；删除确认期间选择变化，会删除后选的文件夹。现在弹窗保存打开时的操作与目标 ID，执行前重新检查当前书库、书、来源和类型。原目标失效时提示重新选择；不会偷偷变成其他操作。被删除的筛选项自动清除。

原生自动回归有 26 项，涵盖保存、取消、目标变化、跨书/跨库/来源和类型边界，以及笔记正文、问答、原书及子文件夹保留。真实前台浮层另核对 41 项，包括三类 512 项列表的首末行选择、移动、四项与混合类型、窄窗和无关状态更新。摘要移动使用合成收纳键，不冒称真实生成摘要正文测试。

## 性能结果及代价

以下为本机 Release 优化编译、隔离合成数据下，完整文件夹组件内容挂载并稳定后的 CPU 中位数。最终源码的对照两侧使用相同的操作保护，只改变完整创建/按需创建，共 48 个新进程、每情形六对交错运行。

| 情形 | 完整创建 | 按需创建 | 进程内存占用中位数 |
| --- | ---: | ---: | --- |
| 筛选，512 个文件夹 | 242.00 ms | 20.37 ms | 121.8 → 22.4 MiB |
| 移动，512 个文件夹 | 236.04 ms | 19.81 ms | 121.0 → 22.7 MiB |
| 筛选，4 个文件夹 | 19.08 ms | 20.18 ms | 21.3 → 21.5 MiB |
| 4 个笔记文件夹，另有 508 个其他类型 | 19.13 ms | 16.97 ms | 21.7 → 21.6 MiB |

大列表两条入口的局部 CPU 约降 92%，行创建次数分别从 1026/1025 降到 12/11。小列表没有证明稳定提速；相对旧版的完整源码补测曾多约 1–2 ms，触发了本批自行设置的“小于 1 ms”调查条件。该失败观察原样保留。相同安全逻辑对照中，四项差值中位数约 +1.10 ms，配对差中位数约 +0.62 ms，少量样本的不确定范围仍跨越正负。采用决定明确接受这点小列表成本与不确定性，不能把原条件改称通过。

先行 96 进程矩阵覆盖 4/16/512、深层级、历史、摘要和移动，也显示大列表收益；它早于最终操作保护修复，与最终 48 进程证据分开保存。不声称上述数字是实际浮层打开延迟、滚动 FPS、整 App 提速或整 App 内存下降。独立查询进度更新在两侧本来都创建零行，不算新收益。没有引入全局缓存或新依赖。
