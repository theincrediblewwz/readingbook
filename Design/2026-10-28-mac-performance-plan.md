# Mac 性能、其他 bug 与界面检查：下一阶段

用户要求在本轮卡顿任务交付完成后，利用真实 Mac 测量性能、寻找其他 bug 和不尽如人意的交互，并提出界面精修建议。本轮已交付 0.23.9/build40（源码 `b164f6c2b1e4c70b393fe17705fdb11b376b12ed`）；下列是下一阶段计划，未把方案或静态判断记为性能结论。

## 测量规则

使用同一已验证 Release、同一 PDF SHA、固定页序与窗口/缩放，冷态和预热态分开，每组 5 次，报告中位数与最差值。所有测试库从工作目录备份再复制，原库保持；服务隔离，不发真实付费 AI 请求，不改网络或系统安全设置。源码、采样、屏幕证据和产物仍只在本工作目录。

计时中不读 AX 层级，截图放到测量后；AX 会引发 PDF 文本结构处理，可能污染数据。不要一边编译一边测，不混入其他诊断程序、OCR/分析、不同动效、透明度、缩放或缓存状态。心跳延迟不是 FPS；RSS 上涨须观察是否平台化，不能直接称为泄漏。

## 第一轮检查

- [ ] 启动：新进程到原文首次可读、主线程等待、峰值内存；当前没有可靠首屏时间戳，需先补齐测量边界，不能拿工具等待时间冒充。
- [ ] 大书导入：每轮空测试库重导同一 1,484 页 PDF，分开记录文本提取/原件复制完成与 PDF 首次可读。
- [ ] 阅读交互：固定 1/8/182/800/1484 页序、1470×843 与 800×600 窗口、343% 缩放，首开伴读不预热；滚动、悬停、拖选另作真实指针检查。
- [ ] CPU/内存：阅读、伴读开/关、重复操作后，准备结束后记录 30/60/120 秒 CPU、RSS、footprint 和 WebContent 子进程。
- [ ] 其他 bug：按复现步骤和日志整理，先修明确错误与性能热点，再做前后对照；保留已有功能和数据约束。
- [ ] UI：先截图记录阅读、书库/工作区、设置及窄窗等主要界面，再列具体可改之处。先给精修建议，区分实际问题和审美选择。

可复用入口：`scripts/sample-macos-hang.sh`、`scripts/native-ui-regression/`、`LocalDiagnostics.swift`。PDF 准备、页索引、引文匹配、Markdown 渲染已有 signpost，可先复用。现有真实视图 harness 是 Debug 程序化回归，不应直接当成 Release 性能排名。
