# Mac 性能、其他 bug 与界面检查：下一阶段

用户要求在本轮卡顿任务交付完成后，利用真实 Mac 测量性能、寻找其他 bug 和不尽如人意的交互，并提出界面精修建议。本轮已交付 0.23.9/build40（源码 `b164f6c2b1e4c70b393fe17705fdb11b376b12ed`）；下列是下一阶段计划，未把方案或静态判断记为性能结论。

## 当前进度

2026-10-28 初查已完成：20次新进程与宽窗6轮暖态基线、窄窗65动作及30/60秒限定记录、启动调用栈、独立缩略图消融对照、书库恢复bug及18步UI证据。缩略图绑定路径对本书有显著成本：禁用它的诊断版启动中位1.597→0.791秒，同书重选1.476→0.364秒。产品仍为0.23.9，下一批需做功能保留的正式修复。窄窗120秒点失焦而排除，严格稳态矩阵仍不完整。见[初查报告](2026-10-28-mac-performance-audit.md)。

## 测量规则

使用同一最终提交的隔离Release诊断副本、同一PDF SHA、固定页序与窗口/缩放，新进程和同进程暖态分开，各取5次，报告中位数与最差值。新进程不代表磁盘冷缓存。消融诊断与正式版基线分开记录。所有测试库从工作目录备份再复制，原库保持；服务隔离，不发真实付费AI请求，不改网络或系统安全设置。源码、采样、屏幕证据和产物仍只在本工作目录。

计时中不读 AX 层级，截图放到测量后；AX 会引发 PDF 文本结构处理，可能污染数据。不要一边编译一边测，不混入其他诊断程序、OCR/分析、不同动效、透明度、缩放或缓存状态。心跳延迟不是 FPS；RSS 上涨须观察是否平台化，不能直接称为泄漏。

## 第一轮检查

- [x] 启动：测新进程→PDF定位匹配/主队列回执、延迟及峰值内存；另取独立主线程栈，不把工具响应或采样耗时冒充像素首屏。
- [x] 大书导入：宽窄各5次空库导入同一1,484页PDF，分记文本提取、原件复制、PDF状态就绪。
