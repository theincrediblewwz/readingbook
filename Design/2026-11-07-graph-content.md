# 导图内容与事件详情

本批面向导图和时间联动，产品版本 0.23.65/build96。交付入口为 `logs/graph-content-20261107/delivery65/final-delivery.json`；只有该回执通过才表示发布、安装和原书收尾全部完成。

## 具体变化

- 独立导图和组合导图的文档节点直接显示原 Markdown 的简短正文。标题和节点 ID、挂载文档 ID、坐标与连线仍来自同一份书项目；摘要只是可丢弃的显示缓存，不写入项目，不另建组件数据库，也不因此把笔记发送给模型。
- 只对能看清文字的可见节点请求摘要。相机坐标不进入请求标识；同一组可见文档平移时不重复启动读取。远缩放低于 45% 时停止这类读取，每批最多 256 篇。编辑、切书、切书库与范围修订会更换归属，过期任务不能发布旧结果。
- 仓库按批核对当前书和全部请求记录，只读每个 Markdown 的前 8192 字节，沿用已有 90 字符摘要规则。短字符串缓存最多 512 项，核对文档记录及普通文件的修改时间、大小、文件/设备身份；热缓存也不能越过原书、回收站、失效记录或符号链接检查。全文编辑、附件和导出仍读原文件。
- 时间卡片先显示事件说明，人物与地点变为紧凑的直接入口，时间和出处合为底部一行。时间筛选仍保留固定详情区域，避免轴的纵向位置跳动。缺少坐标和缺少依据时仍明确显示，不编造路线或出处。
- 原生截图复现了卡片高度停在初始 214 点、正文和原文按钮被裁到下方的问题。改为内容几何变化后的高度反馈；宽窗、窄窗、筛选和原文点击纳入新增原生检查。

## 收益和边界

同一份含 500 个原文单元、32 篇长 Markdown 的隔离夹具，每个版本 6 个新进程、每进程 9 轮。最后 3 对交替运行；前 3 个进程先基线后候选。输出摘要 SHA-256 全部相同。

| 局部读取路径 | 旧路径中位数 | 新路径中位数 |
| --- | ---: | ---: |
| 每个进程第一轮 | 58.97 ms | 20.22 ms |
| 随后缓存轮次 | 58.20 ms | 3.79 ms |

这是有界摘要与元数据核对的墙钟收益，不是整个应用、模型、硬件 FPS、能耗或长期内存收益。证据：`logs/graph-content-20261107/preview-cost-comparison.json` 及 12 份进程记录。节点文字变化不会重建连线几何，也不修改原坐标。

补看既有单条 API 的 32 次顺序调用：冷轮 58.97→61.30 ms，热轮 58.20→44.33 ms；这是补充检查，并非新鲜交替对照。原笔记列表的冷启动没有提速，不把导图批量路径的收益外推给全部入口。

本机只有 Command Line Tools：Release 编译和 49 方法 / 4618 条独立断言通过，不能冒称本机 XCTest。新增 8 项 XCTest 由完整 GitHub 工作流执行。产品视图的 26 项原生检查包括两种导图、编辑刷新、归属、真实 Markdown 渲染、事件摘要、人物与原文操作、窄窗和筛选纵向稳定；完整工作流保留此前全部核心和原生门槛。
