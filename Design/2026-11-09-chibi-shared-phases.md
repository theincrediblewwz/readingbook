## 用户实际能看到的变化

1. **阶段进入共享数据，而不只留在回答里。** 真实模型保存了一个主线父事件，七个子事件按阶段顺序归属其中。组合时间轴可以点选这些阶段，地图与原文随范围联动。没有另建一份地图事实库，也没有把“集结、进攻、撤退”硬编码成固定战役模板。
2. **日期不全，也能看原文先后。** 有日期的资料继续保留日期；日期不全的事件可依据其本身的原文出处进入“原文顺序”轴。默认选能覆盖更多资料的刻度，而不是恰好只覆盖少数有日期事件的轴。这个顺序不等于真实史事日期，更不证明人物实际到过一个地点。
3. **功能协作按需读取长正文。** 指定范围继续授予同样的查询权限，但不再每次都预载整个范围正文。当前页、选句和纯阅读范围仍直接提供正文。按需返回使用真正换行和简短引用，软件为实际读到的片段签发可核验出处；后读片段不能替换前面已经引用的内容。
4. **最新进度在前，点击定位到那一步。** 进度列表倒序显示已发生的操作，标明所属模型请求。点选某一步会打开它所属的请求，滚到那一步并展开实际参数和软件返回。独立详情窗不挤压伴读与对话。

“一次提问”“一次请求”“一次操作”是三层：用户问一次问题，可能需要多次模型 HTTP 请求；一次模型返回又可能要求阅读原文、查事件、打开组件等多个本地操作。截图里的“第 13 次请求”是本次问答中的第 13 次模型请求，不是用户第 13 次提问。列表里每个操作现在都有所属请求编号，因此两处编号能对应起来；不会把每个本地动作都算成新的模型网络请求。

## 收益和适用范围

对照使用同一份冻结的真实赤壁资料、同一原文范围，项目本身不变，不请求模型。

| 对照 | 旧方式 | 本批结果 | 限制 |

## 真实 AI 的效果与不足

使用本机保存的官方 DeepSeek Flash；Key 只在内存中读取。各轮都是**明确冻结基线的续接**，不是从空库一次生成。输入为 43—50 回、94 个原文单元和已有 35 要素、18 事件、11 关系、2 视图；新隔离副本清空旧对话与请求历史，不导入正式笔记。

| 试验 | 实际发生的事 |
| --- | --- |
| `phase2`，8 次 HTTP | 诊断副本输出额度设得过低，第 8 次没有公开答案/参数并因长度结束；没有保存新资料。原样失败保留。 |
| `phase3`，13 次 HTTP | 读取实际原文后提出结构，经原有审阅和局部修正保存 3 个新事件，七个子事件归属同一父级并排序。原 18 个事件的内容、旧 3 条日期和依据保留。但新布局的时间组不一致，打开操作被明确拒绝，不能算已经打开。 |
| `phase4`，2 次 HTTP | 显式续接已保存成果，只复用原有视图；实际打开成功。没有再新建或改写人物、事件、关系或视图。 |

这些真实示例保存在隔离副本，没有自动并入正式书库。正式书籍、笔记和已有分析保留，本批更新的是软件能力。

三轮合计 **23 次 HTTP、1,132,584 个供应商已报告 token**；第 8 次截断请求未报告的用量不在此数内。它不是费用统计，也不是受控的模型提速对照。诊断额度仅作用于隔离副本，不是一本书累计只能问多少次。

真实工作台里已出现七个可点选阶段。火攻阶段实际筛到对应对象与路线；华容道阶段对应的事件有自己的出处，但路线依据不在同一出处范围，因此该窄范围下没有路线，不能为了好看借用别的事件依据。原生已实际跳回第 616 页；最终产品源码又用这份真实成果进行禁网络回放，实际从华容道跳到第 621 页，项目与原文保持，额外模型请求为零。

尚未达到“从空书问一句就自然完成精致战役工作台”的目标。模型仍用较多轮准备和纠错；新布局的选择组/时间组反馈仍需改进。不能把上述续接成果包装成一次生成完成，也不能把原文先后冒充日期或精确行军地理。
