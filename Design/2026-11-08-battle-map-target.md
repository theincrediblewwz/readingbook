# 战争在地图上怎样展开

目标体验：读者问“赤壁这场战争在地图上到底怎么打”，AI组织可交互地图和时间轴，而不是只给一段说明。

| 读者看到或做的事 | 理想效果 | 本批验收方式 |
| --- | --- | --- |
| 提出自然语言问题 | AI复用已保存的人物、地点、事件，选择地图和时间轴，可自由组合现有显示部件 | 使用真实赤壁资料和正常工具链，记录实际请求与保存结果 |
| 看战场 | 地点、事件与不同军队的行动方向清楚；有箭头、简短名称，点击可看依据 | 正式渲染器检查箭头方向、端点、点选及原文入口 |
| 选时间范围 | 同一年的不同月日也能分开，地图上的事件和路线同步筛选 | 用火攻前后的小范围对照，不只测试跨年份 |
| 日期或路线不确定 | 仍能显示有意义的推演，虚线、标签或详情说明依据；不把推演伪装成原文明说 | 区分事件事实、日期依据、地点参考和路线判断 |
| 再问一个问题 | 可补充另一支军队、另一阶段或另一个组合，不用从头分析整本书 | 复用同一组ID，保留已有修正与分析 |
| 回到阅读 | 点击地点、事件或箭头可查看相关原句，跳回书中位置 | 原文范围、页码和出处按真实书核对 |

界面沿用全幅地图、简洁浮动时间卡与详情气泡。说明放进详情，地图主体用于看点、方向和事件；日历仍使用原书记法，不暗中换算。缺少可靠日期时可以用叙事顺序组织；现代底图上的参考位置和示意连线不会冒充精确古代道路。

实现首先补通用能力，不按书名硬套战争模板。路线是共享关系的空间信息，引用现有地点、人物和事件ID；组件只保存显示配置。AI可以主动提出进攻、撤退、调兵、运输等组织方式，标签可以由问题决定。

当前确认的三个缺口：组合地图没有方向路线；两个时间轴入口把月日丢成了年份；事件与时间缺少独立的依据分类。本批先修这些，再用真实模型与真实赤壁资料核对整体效果。合成用例仅验证边界和几何，不作为真实生成效果。
