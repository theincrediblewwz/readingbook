## 改了什么

| 项目 | 结果与评价 |
| --- | --- |
| 日期筛选后路线消失 | 修复。地图与时间轴都保留时间未明、不可比较的记录，路线用虚线和“时间待定”说明，不假装已匹配日期。明确在范围外的路线仍隐藏；达到128条显示上限时，已知时间的匹配项优先。 |
| 事件日期与路线日期 | 保持分开。刘备移兵樊口的路线在第559页，其关联的伏兵事件在更后面；直接借用事件日期会制造错误。本批没有改写原有时间数据，也未新增日期存储字段。 |
| 重复原文回传 | 有同数据收益。仅在对象/关系查询的 evidence 中，将整段、逐字节一致且本轮已提供的原文换为已有 sourceRef；旧简介、未知片段、局部引文、额外字段与版本 hash 保持。10处重复引文的工具回传从21,175B降至7,593B，少13,582B，约64.1%。这是离线重放真实记录，不能等同于模型整体提速。 |
| 保存与打开状态 | 宿主记录工具来源；同一提案的最新审阅决定取代之前的待审阅状态。组件目录成功不作为打开凭证。早期失败明确记为尝试，保留后续实际成功回执，不把所有失败一并抹掉。 |
| 紧预算收尾 | 修复相关回归发现的问题：先按实际请求体计算可容纳的正文，放不下才收缩，不预先砍半。仅实际发送的片段保留引用权限。 |
| 界面 | 时间未定说明放进小按钮气泡；没有增加新的常驻解释段。真实地图的大圆标记、密度和初始相机范围仍待精修。 |

AI仍收到原本的干净正文；sourceRef只是对已经收到的同一段文字的短引用，不再发第二份原文。保存时软件展开成原来的 unitID/quote，再跑原有逐字与范围校验；共享资料本身不变。请求详情保留实际发给模型的回传，不伪造一个与真实请求不同的展示版本。
