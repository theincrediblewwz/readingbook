## 这次要形成的体验

导入后先阅读。选择分析范围、希望看到的组件和分析精细度，AI 提出一份可编辑的阅读安排。开始后，已核验的译注、人物和事件陆续出现；分析全书不挡住当前页聊天。暂停后可以缩小范围，原有结果保留。再次遇到人物，先读本地已有介绍，只补新增发展。

阅读中的解释默认像熟悉这本书的老师带读；需要时切到考据。对话另有独立的“纯粹阅读 / 功能协作”开关，不能把解释语气与工具权限混成一个开关。原书、用户 Markdown、来源和权限保护保持；自然的表达不意味着把背景常识冒充原文。

已批准的阅读口径：标准阅读可省去逐段复述，精读保留可选的逐段核对；“已分析范围”与“逐段核对覆盖”分别统计。旧回执与原有核对记录保留，不批量重写，不为标准阅读补造回执。并发上限五路、默认老师带读也是用户已说明的要求，不重复列为待批准事项。

## 原生落地与实际边界

本轮已接通执行配置、增量检查点、范围重选、纯阅读/功能协作、老师/考据、句旁译注和内嵌组件、分组懒详情、请求历史及渲染更新。最终通过的源码与Actions记录以根README为准，下面的“当前证据”仍是0.19审查基线，不表示这些旧缺陷尚未修。

- 基础阅读始终保留；附加讲解、要素、译注、回顾等可删。标准分析与逐段核对分别统计，不伪造旧回执。章/书末回顾可按需读取安全范围内的已保存分析，超长全书未增加无限上下文或假通读保证。
- 上限包括前台对话。配置标准分析可使用多条后台线；上限大于1时保留一个问答位置。精读因真实回执批次串行，采用单条后台分析线。请求和用量共用预算，不能每开一条就重置预算；后台AI与手动正文编辑并行继续留待下一批。
- 同仓库actor增量合并、稳定操作ID去重；同字段或并行新身份冲突保留已存结果，再有界重读，不用旧整书快照覆盖。原书、用户Markdown、回收与恢复链保留，无破坏迁移。
- 已有简介仅在当前可见来源均有效时复用；混有未来依据的聚合简介保持隐藏，不把它拆成臆造的事实版本。没有强行生成或覆盖一套全书老师传记缓存。
- PDF采用装饰差异与分批绘制，几何仍在主线程；未采用有平台差异的PDFPageOverlayViewProvider替换方案。Web装饰、字号与主题独立更新，正文/公式DOM保持。全文JSON合并/验证仍有成本，不能据此宣称大书所有卡顿已根治；需Mac采样。
- 请求历史保留耗时/字符计数及实际工具产物，不保存密钥、思考原文或完整请求参数。没有句级精确锚点的译文不会猜测悬停位置；没有本地内容的悬停不会自动付费。

## 最小一致架构

### 计划、范围和调度分开

实际由 `ReadingExecutionConfiguration` 描述组件需求、精细度、步骤及频率、逻辑块策略和用户并发上限，AI 在方案中建议粒度与并发；`SmartReadingSession` 冻结源单元、哈希与分析检查点，AppStore 的独立 worker 执行队列。用户缩范围不删除已提交产物；只有原文和配置仍匹配的成功检查点可复用，改粒度或步骤可能重做相关分析，不能把旧结果当成新方案全部完成。

页/章/自适应是逻辑块，不修改导入的 `SourceUnit`、原始页码或锚点。块内仍保留每条结果对应的原始 unit/quote/hash。未可靠分章的 PDF 不把“当前章”伪装成已识别的完整章节；可采用受 token/输出预算约束的相邻内容块。

标准阅读以问题、理解、可用伴读和组件内容为目标，不强制先做每段复述。精读允许开启逐段核对。新“已分析范围”与旧“逐段核对覆盖”分别计算；旧回执和完成记录不删除、不降格、不用于伪造新覆盖。

### 并行请求，串行可靠提交

实际同时请求上限为 `min(5, 用户上限, AI计划建议)`，服务端另行限流不由本地推定。前台聊天/当前页解释优先；上限大于1时固定保留一个前台槽。AI 规划不能突破用户上限或预算，相互依赖的阅读步骤仍有顺序；配置规划独占，不能让多个工作线程各自改写本书方案。

当前后台不借用预留的前台槽；总上限为一时，请求串行排队，不承诺两个 HTTP 同时进行。标准阅读可并行，精读因共享真实回执批次而采用一条后台线。

每个任务拥有独立 reader、上下文、进度、取消句柄、源范围和运行 ID。宿主统一预留/扣除请求与 token 预算，不能为五条线分别 reset 同一总预算。取消立即停止派发与网络；已提交内容保留，未完成响应不记为产物。

唯一 Repository actor 的真实入口是 `commitAIResult(base:result:operationID:)`：读取最新项目，验证原文字节与受控字段，对基线、结果和最新状态三方合并，按操作ID幂等提交；不让旧 `BookProject` 快照整本覆盖新结果。同字段冲突保留已存内容，有界重读重试；用户 Markdown 继续使用已有的授权、差异审阅和恢复链，不因后台分析取得覆盖权限。

每个核验成功的产物批次都发布，可见的实体、译注、事件与组件变化不必等到全书结束。请求历史展示真实操作和结果链接；不把“接收工具参数”显示为“已保存”，也不把待审阅方案显示为已应用。

### 截至阅读位置的本地复用

身份候选与事实投影分开：名字/别名索引帮助复用稳定 ID，事实投影只包含当前阅读光标之前允许看到的内容。已有简介、译注和解释先查本地缓存；本次原文提供新发展时才追加。背景常识可以帮助老师式讲解，但保持独立来源类别，不改写书中证据。

对话采用两个独立维度：

| 维度 | 默认 | 另一选项 | 约束 |
| --- | --- | --- | --- |
| 对话用途 | 纯粹阅读 | 功能协作 | 前者不携带组件写入 schema 与执行账本；后者只带本轮获准接口。 |
| 讲解方式 | 老师带读 | 考据 | 前者自然补背景，后者聚焦出处；都不伪造来源或绕过防剧透。 |

### 按页准备、按需呈现

`ReadingPageSnapshotCache` 以当前页原文及相关锚点/对象输入为键，不用全局 projectRevision 使所有页面一同失效。后台准备匹配，主线程分批补可见页装饰，旧任务按 generation 丢弃；分组详情展开才创建富内容。当前阅读页优先调度和邻页低优先预取仍属候选，不作为本批已实现能力。

PDF 独立覆盖层需要做 macOS API 可用性与命中验证后选型，不能直接照搬返回 `UIView` 的 iOS 示例。现有 Annotation 方案先保留安全回退，渲染层不得修改持久原 PDF。Web 阅读使用稳定锚点索引和差异装饰，不每次整体替换正文 DOM。气泡只渲染获准声明组件，限制数量与高度，地图/图谱展开才启动重绘。

## 实施与验收顺序

1. 整体交互稿与设计口径已获用户批准；五路上限、老师默认、可改范围/组件/步骤不再重复询问，开始按本顺序实施。
2. 先修确定接线/展示错误：暂停范围、取消中文状态、双层表面、导航空白、空态居中、进度重复、Markdown/引用显示。此阶段不假装已支持并发。
3. 建立增量提交与统一任务/预算，再接前台问答与后台队列；用临时书库测试交错提交、取消、冲突和恢复，不拿真实用户库试迁移。
4. 接逻辑块/步骤频率与组件要求，逐批发布结果；建立截至阅读光标的实体复用和老师/考据投影。
5. 基于用户大书在 Mac 采样，比较装饰、伴读列表、任务开始/暂停的耗时，再确定 PDF 覆盖层与缓存方案。渐进渲染、分类折叠和布局一致性在 800×600 与宽窗都测试。
6. 仅在原生实现完成、必要 Core 回归和双架构 Actions 通过、下载包与资源核验后交付新安装包。Windows 静态审查和本交互稿不算这一步通过。

本提案不要求批量迁移原书、用户 Markdown 或现有对象 ID；不删除旧账本、已有产物、回收与恢复关联。新元数据采用可选扩展并保留旧读取路径，旧项目按原语义打开。若实现中发现必须变更持久格式，先提出具体兼容/回滚方案，不能把“迁移为零”当作已经验证的事实。
