# ReadingBook：先设计，再还原

## 当前进展（2026-10-16）

用户选定第 1 版「霜银 · 钴蓝」。已完成阅读、地图、导图、笔记、插件、模型设置六个视觉目标，并在 `../prototype-frost/` 实现全软件交互稿。本地预览：http://127.0.0.1:4178/；效果图画册：http://127.0.0.1:4178/design/。其余页面使用同一套壳层与组件，不逐页另生成图片。交互、宽窄窗与修正记录见 `../prototype-frost/design-qa.md`。

本节记录浏览器设计阶段；OCR、模型连接和逐段分析明确模拟，没有调用付费模型。随后用户已批准 0.11 原生还原并已通过Actions编译打包，具体见根README与原生QA；不把浏览器结果当成Mac验收。下面为本轮设计过程与既定验收约束；旧“待选”状态属于历史阶段。

本轮按用户要求改变 UI 工作方法。基线是 `473b165`（0.10 源码为 `1638ebb`），先盘点全软件的页面、按钮、选项和状态，再画效果图，再制作可点击交互稿，最后才还原到 SwiftUI。

## 这一轮的交付范围

1. 图文盘点册：现有截图、全页面与弹层清单、控件行为、拍摄缺口、源码位置。
2. 一套视觉方向的首张阅读效果稿，以用户给出的真实旧版截图与既有品牌规范为参考。
3. 设计评审后继续出地图、导图、笔记、模型设置等关键场景，串成交互稿；本轮不跳过效果稿直接改 App。

## 视觉证据的边界

- `evidence/01`、`02` 是用户先前提供的 Mac 阅读窗口；`03`、`04` 是菜单与标签局部。具体 App 构建版本未知，不标为 0.10 现状验收。
- `inventory-*.json` 来自当前 SwiftUI 源码。页面与控件确实存在，实际尺寸观感、材质、悬停、焦点和动画需 Mac 实拍。
- 盘点册的结构图只表达区域和信息关系，不是原生截图，也不是已选定的新 UI。
- 新生成效果图明确属于设计提案，不代表 App 已实现，也不证明交互可用。

## 设计目标

- 原书是主画面。目录、伴读、对象详情和设置按需展开，收起后空间还给正文。
- 自有书页标记与现有图标语义延续。用户最新要求探索替代松墨绿色的配色与材质；新交互稿已选霜银与钴蓝。原生玻璃用于工具与浮层，长文保持稳定纸面。
- 常用按钮命中区域拟为 44pt，导航行 48pt；字号和留白同时设计，不靠缩小文字挤下所有功能。这是待评审的设计值。
- 导航只设一个主入口；当前书、AI 服务和明确命名的精读任务使用顶部独立悬浮组，不再占固定窗口栏。翻页、缩放、查找等阅读操作集中在一处。
- 全行可点；图谱单击详情、双击文档、拖动移动、端口/右键连线。保留键盘入口，不把隐蔽手势当成唯一操作途径。
- 地图只有一根双端时间轴，事件详情沿浮动时间框展开；节点列表在右边。工具不能挡住正在操作的对象。
- 每个主要页面都设计默认、展开、选中、空、加载、失败、忙碌、删除/恢复、窄窗状态。
- 800×600、1080×760、1440×1024三个尺寸都要在交互稿中评审，记录侧栏/面板溢出和焦点回退规则。

## 从效果图到交互稿

### 阅读效果稿 V2（悬浮布局已认可，配色与材质待选）

首稿 `concept-reader-v1.png` 未获选定。用户要求书名、AI 服务和精读按钮悬浮；伴读变为悬浮框；左侧导航可收为一个点状入口。已据此生成 `concept-reader-v2.png`，盘点册展示的 `concept-reader.png` 是 V2 副本。两稿都是生成的视觉提案，不是原生 App 实拍；画面中的书页与数学内容仅供排版示意，真实实现继续显示原始 PDF，不能将示意书页当作 OCR 或公式准确性证据。

V2 取消固定顶栏背景、全高侧栏和全高伴读列，书页成为连续画布。左上书名、右上服务与任务、下方阅读工具分为独立玻璃浮层；伴读是有拖动柄、收起和关闭入口的右侧浮窗。用户已认可此方向，但要求多做不同风格后再选定主题；认可布局不代表交互已通过。

样式定稿后，必须覆盖全软件，按下面七组展开效果稿和交互稿，不能以阅读页完成替代全软件完成：

| 范围 | 后续需要设计的界面 |
| --- | --- |
| 壳层与书库 | 点状导航、展开导航、书籍切换、导入、全局菜单、添加组件 |
| 原文与伴读 | 原始 PDF/文本、目录、查找、伴读、译注对照、思考卡、原文返回 |
| PDF 处理 | OCR 范围与预算、密码解锁、文字高亮、区域批注、批注恢复 |
| 时间与地图 | 地图、单轴双端点范围、浮动时间框、事件清单、事件与对象详情 |
| 图谱与要素 | 无限文档导图、右侧节点列表、关系图、共现图、AI 自定义类型卡片 |
| 笔记与知识 | Markdown 编辑/预览、AI 选段与合并保存、知识检索、全书总览、回收站 |
| AI 与扩展 | 服务列表与表单、连接测试、Max、高级参数、插件库、读书法及执行回执 |

每组都覆盖默认/选中、展开/收起、空、忙碌、失败、窄窗和键盘焦点。主题强调色不能兼任所有状态色；错误、警告、成功、原文/用户内容/AI 内容须有文字或图标辅助。地图共享阅读范围和对象身份，未知时间/坐标明确呈现；文档导图可编辑、派生关系图只读的能力区别需要可见。Max 表示配置支持的输出 token 上限，不包装成保证模型能力的模式；未知规格要说明。插件停用、移除节点、移入回收站与永久删除保持各自语义，恢复入口明确。此处只记录约束，不声称这些效果稿或交互已完成。

交互稿必须补齐下列规则：

- 导航点的视觉尺寸可小，实际可点区域至少 44pt；悬停显示“展开导航”，键盘可聚焦，支持快捷键，不能只靠猜测图形。展开后有图标与文字，完整承接书库、固定工作台和本书已启用组件；原组件去重规则保留。
- 伴读收起后留下可识别的恢复入口，关闭后可从原入口重开；面板拖动限制在可见范围，窗口缩小时不能跑到屏幕外。拖动柄、面板内部滚动和文本选择不争抢手势。
- 浮层不得遮住正在阅读、查找或回跳的原句。打开伴读和定位命中时调整阅读视口或面板位置，不能靠截图中手工留下的空白假装解决。窄窗一次只展开一块主要面板；用户的原始 PDF 不为浮层重新排版。
- 顶部命令与底部阅读工具在阅读时可淡出，悬停、键盘聚焦或调用命令时恢复；弹出菜单、任务进行中和屏幕阅读器使用时不突然消失。“减少动态效果/降低透明度”需有稳定退化。
- 工具名称保持明确，任务在运行、暂停、失败和继续时反馈真实状态；“处理覆盖”与“理解正确”继续分开。

地图、导图、笔记与设置应复用这一套浮层规则，不能只更改阅读页。先确定 V2 的密度和视觉，再出其他场景及其展开/收起/窄窗状态，然后串成交互稿。之前的功能要求保持在原任务范围，不因设计阶段而取消。

效果图先决定密度、层次、布局和视觉。交互稿再验证：收起/展开→阅读→选段→伴读/问答→返回原句→写笔记→保存→导图→删除/恢复。地图与模型配置分别补一条完整任务路径。

交互稿评审需要能点击主入口、菜单、面板、选项、关闭和恢复；输入框及保存流程使用明确的示例数据。动效规格要说明触发、方向、时长及“减少动态效果”的回退。每一阶段的缺口单独标明，静态图片不算交互验收。
