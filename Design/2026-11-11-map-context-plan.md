# 同一资料、单张详情卡、少量往返

希望达到的效果：点地图上的行动时，原处只展开一张卡片。卡片先讲这次行动，再显示相关事件与原文依据，不同时弹两张；地图和时间轴仍是主体。AI 改图标时，一次看到当前获准资料实际存在的类别，不先翻很多页资料。缩小地图时，行动能沿共享事件的父子关系归组，不能因为地图只展示地点，就丢掉所属过程。

本批实现：

1. 组合地图把当前行动选择交给现有详情卡，卡内显示行动和关联事件；未配置适合详情卡的旧地图保留独立行动浮卡。关闭、点空白、切事件/时间/范围应清理旧选择，避免幽灵卡片。不同选择组不相互吞掉内容。
2. 打开地图视图时附一份有界的实际事件/行动类别计数，复用已切片的当前提问投影；不返正文、不扩大范围、不扫描文档文件、不新增资料缓存。目录不全要明确告知，不装作全量。
3. 在当前来源许可内为路线投影计算事件家族；地图点源是地点时也能正确归组。只在祖先及其元数据都获准时命名；禁止借用域外父级、编日期/路线/坐标。
4. 用上批冻结的赤壁与生态调查资料做真实 AI 请求和原生界面验收。先保留现场，再运行新请求；保留公开发送与返回内容，Key 不落日志。

单对象素材覆盖、完整战役热度外沿、现代地名密度和层级时间轴排后续，不把这批越做越大。先测实际收益再保留优化；本地迭代通过后集中更新安装版并同步一次 GitHub main，不逐小改动运行云端发布。原书、笔记、分析和用户已有改动保留，构建与清理均在本工作目录内。

真实调查对照追加：同一 kind 在事件/行动只列一行，分别计数；素材修改合并指定类别，明确空对象才清空。原始工具参数重复字段在进入宿主前反馈具体键/行列，沿用现有有界草稿修正，不默取最后值。现场保留 shared-kind-update-case.json。
