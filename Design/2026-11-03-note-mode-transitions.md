# 便签切换阅读模式后的错位修复

目标版本：0.23.42 / build73。已同步main、发布并替换本机安装，正式原书两次正常启动检查完成。

## 复现与原因

同一本 1,484 页 PDF 的隔离副本，第 104 页的“你好”便签在整页下正常；切到适宽，纸条跑到前一页；左右连续时留白存在而纸条不可见。原书及笔记未修改。旧版真实窗口截图保存在工作区 `logs/note-mode-transitions-20261103/references/`。

保存的页码、归一坐标和原生 PDF 转换均正确。问题在最终显示：`PositionNoteMarginLayer` 用完整页高放置便签，再套一个默认居中的视口 frame。适宽页高超过窗口时，整个内容被向上移了溢出高度的一半。原书副本一次记录应在 y=32.23 的便签宿主实际变成 y=-363.5，偏差约 396 点。纸条与连线会一起错位，因此看起来像绑定到了前一页。左右模式的纸条会直接跑出可视范围。

## 修复

显式将该视口 frame 对齐到左上角。保留原来的逐页留白、原书坐标、裁切、同比缩放、扇形展开和纸书动画机制。没有迁移或重写笔记，没有更换原 PDF，也没有通过扩大容差隐藏偏差。

上一轮测试只验证了发布出来的坐标与 PDF 页框，缺少对最终 `PositionNoteNativeHost` 位置的核对。本次新增真实 `ReaderWorkspaceView` 的原生回归，直接读取宿主视图在阅读器中的最终边界，并与所属书页留白比较；原文锚点另外以独立、未加宽的原 PDF 为基准。

这是一项布局正确性修复，不把检查数当成不同用户操作数，也不冒充新的 FPS、内存或模型响应速度收益。旧失败回执原样保留。
