# 伴读出处与只读 AI 工具优化

本批目标为 0.23.28/build59，基线为 main `4fb137ce7edef8e492c16cbb3ada4c4b6b5b5d5e`。本机实际产品编译与八项新增保护检查通过；最终完整 CI、发布、安装和原书验收完成后补齐交付记录。

## 实际采用的改动

只读工具执行仍先检查参数、注册阶段和逐段权限，再在项目副本中运行回调。新路径先比较整个项目的排序 JSON 字节，完全相同才省去重叠的逐字段编码，并继续验证回收站保留记录。编码失败或任一差异走原来的完整校验及报错路径。标准分析完成的额外宿主权限检查始终保留。没有按 `readOnly` 标签直接信任第三方回调，没有缓存跨书或跨请求的校验结果，也没有改变写入工具流程。

多层伴读使用本次卡片的实际出处列表，少于十二个不同引用仍直接查找；较密集时只索引所需的第一个存储锚点及原文单元，找到全部目标即停止。保留重复显示顺序、缺失原文的提示、字节原样的引句及第一个同名记录优先规则。它是显示元信息查找，点击出处仍由原有原文版本、哈希与精确位置校验负责，不是新的阅读授权。

索引在 LazyVStack 实际卡片内准备，避免打开页面时为尚未显示的整段历史提前建表。同一纸面计算中的层与资料对读筛选各复用一次。主伴读面板、对话模式、已有笔记和原书内容没有改写。

思路参考 Apple 的 [SwiftUI 性能定位](https://developer.apple.com/videos/play/wwdc2023/10160/)和 Swift 官方的[值与引用语义](https://www.swift.org/documentation/articles/value-and-reference-types.html)。以下收益来自本机实际对照，不从这些接口说明推断。

## 对照结果与边界

两轮正式实验与卡片补测共 176 个新进程。只读工具每种情形合并全部八对 AB/BA 样本，不挑较好的轮次。比较真实优化编译的完整 `registry.apply`，包含处理器、原文范围、结果生成和全部保留校验；排除夹具建立及最终输出编码。每对核对四组完整响应和完整项目字节；响应只统一 JSON 对象键顺序，数组和字符串字节保留。写入工具只在计时外固定自动审计的 UUID/时间后比较。

| 固定合成场景 | CPU 配对中位变化 | 每次节省 |
| --- | ---: | ---: |
| 小书知识查询 | −18.52% | 约0.176 ms |
| 大书知识查询 | −8.80% | 约9.25 ms |
| 大书已有分析目录查询 | −25.38% | 约9.37 ms |

工具夹具包含12或1484单元、已有分析和不同规模的知识/对话/笔记元信息。小、大写入对照未出现越过既定门槛的回退；只读工具额外峰值 RSS 上限约1.98 MiB，密集卡片约560 KiB。卡片空内容和三个出处基本不变；重复/缺失出处多约0.020 ms，靠前的十二个不同出处多约0.0034 ms，均在预定绝对开销门槛内。不能把这些极短调用的高百分比波动当作显著改善或隐去。

早期跨多条记录批量准备3000引用的测试约快89%，仅用于局部算法诊断；最终产品按实际卡片准备，以128引用补测作为界面集成收益依据。未测整页布局、Markdown渲染、完整界面耗时、FPS或模型网络等待，不声称它们同幅度提升。

## 否决与验证

第一版只按引用总数建整书索引，重复/缺失情形多约0.34 ms，未通过预定门槛，已否决并保留完整数据。第二版按不同引用和实际所需位置准备，再检查惰性卡片边界后才采用。初次知识查询测试夹具的人名未出现在授权原文中，被现有范围过滤正确隐藏；补齐合成输入后重测，没有放宽过滤规则。

八项新增检查覆盖真实知识查询不写项目/审计、只读变更的原错误及回滚、Unicode等价文本不得替换原文字节、非法回收状态与不可编码数值仍拒绝、标准完成权限、阶段/回执先于回调，以及来源重复/缺失/跨快照隔离。本机使用实际测试源码和轻量断言层，标记为非XCTest；真正完整XCTest仍在GitHub执行。

对话和知识库的按需读笔记、空历史提前退出与一次冻结内共享已经存在。本批只读审查保留这些机制；剩余附件准备和可见知识行成本未有新收益证据，没有混入产品。详见 `logs/companion-tools-20261031/remaining-components-audit.md`。

原书、笔记、分析、偏好和用户未提交文档均受保护。全部新代码、实验、缓存和日志在工作目录内。交付及清理的最终入口将在本文件补齐。
