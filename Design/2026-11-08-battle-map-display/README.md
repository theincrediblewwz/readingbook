# 地图信息展示草图

本地文件 `01.png`、`02.png`、`03.png` 对应聊天中依次出现的三张草图。使用内置 Image Gen，根据用户提供的实际地图截图和经典战役地图生成；提示词在本目录。用户已选择组合：左侧图例素材、底部进程、点选浮动详情，采用第一张路线与UI、第二张范围和图标；融合稿为 `04-融合稿.png`。图像暂留工作区，未选定的方案不作为产品资源上传。所有地图、路线、区域与引文均为交互构想，不是程序已经生成的真实赤壁分析。

## 当前画面判断

唯一截图步骤：打开有火攻、撤退和多个地点的地图。功能可点选，信息显示较差。用户提供的原始截图已保存为 `current-overlap.png`，原图复看确认是地点、事件和路线三层标签相互遮挡。

| 画面问题 | 对阅读的影响 | 设计约束 |
| --- | --- | --- |
| 同处重复显示地点、事件标题和行动名称 | 看不出哪条说明属于哪个点 | 地图只常驻地点名及简短事件符号；只展开选中内容；同处聚合成数量标记 |
| 所有事件使用近似钥匙的定位图钉 | 无法区分打仗、行军、撤退 | 采用统一的语义图标目录；未知类别有中性后备，不让模型任意输出失效的系统图标名 |
| 远缩放时标签仍全部出现 | 小区域成为一堆胶囊 | 随缩放分级展示、屏幕坐标避让、保持选中对象优先；不要随机跳动 |
| 时间、出处与路线判断挤在地图上 | 主体地图被说明占满 | 简短标题在地图，完整依据和不确定性放详情；不可只靠颜色表达 |
| 同一年的短日期轴重复很多刻度文字 | 相邻日期仍难分辨 | 按可用宽度挑选不重叠的真实刻度，当前日期保持可读 |

这是一张截图支持的局部审查，不代表完整键盘、VoiceOver、对比度或所有地图缩放状态均已验收。原生功能回归与视觉问题分别记录。

## 三种信息组织方向

| 文件 | 组织方法 | 主要取舍 |

| 01.png | 选中一路，显示一个详情，其他事件聚合；紧凑时间卡 | 接近现在的工作方式，改动少。生成器误画了当天日期，实施时必须移除，不能用现代日期表示古代事件 |

图中的助手图标、图例用语和地理位置还需按现有产品与实际依据校准。选择结构后再精修，不直接把位图当可交互产品。

## 功能先行的底层约束

1. 继续共用人物、地点、事件、关系与原文锚点。组件不复制一份独立事实；视图只保存展示和筛选配置。
2. 现有行动仅有起终点与途经地点时，只能称“方向示意”。光滑曲线不能让读者误认为已核定古道或真实河道。
3. 有详细依据时，后续可在共享空间记录上增加地理矢量：有序坐标、必要控制点、区域环、出处、时间、精确程度。不能只存屏幕像素或某个组件的私有画布。
4. 区域的范围和依据属于共享资料；颜色、线宽、虚线与选中高亮属于显示配置。未知边界不能由模型为美观补齐。
5. 图标目录应覆盖火攻、战斗、行军、撤退、渡河/航行、围城、驻营、会盟、运输、抵达等语义；也为非战争书籍保留中性类别。先用已有矢量图标体系，再补确有必要的符号。
6. 标签布局以视口为单位，先裁剪不可见对象，再做有上限的聚合与避让。几何不因每帧平移全量重算；缩放后按屏幕误差选择曲线细度。
7. 蚂蚁线和呼吸效果只用于选中路线/区域，共用一个时钟；后台、不可见和减少动态效果模式下停用。动画不改变实际路线和出处。

下一步先修真实模型整理中的叙事时间刻度和审阅续接，再按已选择的融合方案做一套可操作原型，验证拥挤、远缩放、点选和时间筛选后才进入正式界面。

## 素材与插件组合的约定

用户明确要求：战斗、火攻、行军、撤退等能够作为独立素材/插件自由组合。图标由软件提供，AI按这本书和这次问题从素材库选取、组合，不固定成一套只能用于某场战役的模板。

- 每种素材有稳定ID、语义、矢量图标和可调样式，能够单独选用、增减和扩展。图例只显示本次实际用到的素材，其余按需查找，避免把全目录塞进每轮AI指令。
- 点、方向路线、详细路径、区域、进程轴和详情卡作为可组合元件，绑定共享对象ID及出处。行动事实不因切换图标、视图或配色而重复创建。
- 同一个事件可以同时绑定战斗图标、火攻路线、影响区域和详情卡；它们是同一事实的几种表达，不为了显示不同图标重复创建事件。图例默认只列本次真正用到的素材，素材库其余项目按需打开。
- AI可以自行组织新的行动类别与阶段，如运输、会盟、侦察；未知素材使用通用后备并允许补充素材，不因不在“战斗/火攻”枚举就无法表达。
- 图例、进程与详情组成当前布局配置，可保存或后续调整；它们不等于作品类型，也不在导入书时永久定死。
- 插件提供声明式素材与能力，保留既有权限/来源校验。这一段是后续实现契约，0.23.69尚未实现该素材目录。

## 时间轴作为骨架，阶段作为分组

用户补充确认：下方不能只放集结、进攻、撤退三个粗略按钮。数据是底层，时间轴、地图和其他组件是组合展示它的渠道。最新修订图为 `05-时间轴融合稿.png`，它替代04稿底部的粗阶段条，保留其余融合布局。

日期、时刻、时间段和相对先后共用一套时间资料。先展示时间刻度，再在对应位置显示何时进攻、火攻、开始撤退、抵达某处。阶段是相关事件的分组与时间区间，可以展开细节；不得独立创造一套等距序号来冒充时间，也不按屏幕上几个按钮反过来生成事实。

修订稿用真实示例书中的时间文字作为设计词汇：604/605页记十一月二十日，606页写将近三更起风，617页写走至五更、乌林之西，618页写天色微明。它们不能自动换成现代钟点；前文纪年为原书所写的建安十二年，不能按外部历史常识擅改。火攻与开始撤退的精确时刻在这些片段中没有核定，稿中放在待考区间，不伪造一个准确点。阶段、区域和几何位置仍为交互示意，不作真实战役推演结果。

下一阶段底层需要补足同日时刻和有出处的相对时间关系、统一叙事刻度，并让所有组件使用同一个时间查询。已有年月日数据不迁移重写，旧记录不凭猜测归一化。时间缺失时仍允许展示事件、地点和行动，同时说明已知先后与未明部分；不能因为暂缺日期就锁住其他组件。

## 已核对的实现参考

2026-11-08核对了下列一手资料，作为下一阶段实现依据，不表示正式产品已经采用。

- 原生MapKit已有标注聚合能力，同一分组的标注碰撞后可合为一个簇，默认不自动启用。先评估它能否接入当前复用渲染器，再决定是否需要额外避让算法。[Apple：clusteringIdentifier](https://developer.apple.com/documentation/mapkit/mkannotationview/clusteringidentifier)
- 碰撞范围可以按矩形、圆形或不碰撞处理；长文字应纳入整体碰撞框，不能只给小圆点避让。[Apple：MKAnnotationViewCollisionMode](https://developer.apple.com/documentation/mapkit/mkannotationview/collisionmode-swift.enum)
- 复杂曲线可评估原生路径覆盖物，使用CGPath并在数据改变时明确失效重建；是否替代现有MapPolyline须先做原生性能与输入对照。[Apple：MKOverlayPathRenderer](https://developer.apple.com/documentation/mapkit/mkoverlaypathrenderer)
- 地理交换可采用GeoJSON的LineString/Polygon与properties，但标准的LineString是位置之间的线性插值，不能把贝塞尔控制点塞入coordinates冒充标准曲线。若编辑时保留曲线控制点，应另有明确可选结构，导出按声明误差展开为折线；坐标次序、基准、跨日界线和区域闭合另验。[IETF：RFC 7946](https://www.rfc-editor.org/rfc/rfc7946.html)

上述“先复用原生聚合”“曲线按需投影/离散”“共享数据而不是每个组件画一份”是结合现有源码作出的方案判断，仍需对照测试，不能仅因框架提供接口就宣称已经改善。
